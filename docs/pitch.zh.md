# 多一个人 · 中文讲稿

**一句话：换个时间，不必拿已有的席位冒险。**

## 90 秒讲稿

你已经报上一个工作坊，但临时有事，想换到另一个时间。难道要先退掉手上的位置，再赌新场次还有空位吗？

「多一个人」让大家同意同一份完整换位方案。只有拿到你认可的新席位，才释放原位。所有人的换位一起完成；任何一项不成立，整份方案就失败。

看这个例子：小林有周六上午，小陈有周六下午，周日还空着一席，小雨在候补。小林去下午，小陈去周日，小雨接上午。同样三个位置，参加人数从两人变成三人。

现在，请试着让它失败。少一个人的同意，原位全部不动。如果撤回先于执行进入合约，旧方案也不能再生效。

合约已经在 Monad 测试网上运行。最新证明记录了缺签被拒、撤回不丢席位、旧方案被拒、重新同意后接力成功，以及重放被拒。测试里的合约钱包都由同一个控制者管理，所以这证明了机制，没有证明真实用户采用。

完整钱包浏览器流程也已通过三个本地测试账户的验收，和真实 Monad 证明分开记录。

我们面对的是两家独立机构愿意共同承认规则，却不愿把所有名单交给对方的场景。如果只有一家主办方，用现有数据库通常更简单。

下一步，要验证两家真实机构是否愿意预留名额、承认结果。今天，请先检验这个承诺：没有人需要先退掉自己的位置。

## 关键问答

- **为什么不用数据库？** 数据库也可以原子提交。一家机构或愿意共用同一个管理员时，数据库通常更省事。合约的意义是把多家机构共同接受的执行规则交给公开程序，参加者签完整方案，任何人可以代发和复核。
- **哪里创新？** 创新主张是面向真实预约问题的条件换位接力产品，不是原创匹配算法、原创原子交易或全球首创。已检索的票务与签到项目不是完整竞品全集。
- **为什么 Monad？** 使用兼容 EVM 的签名与合约工具，并明确区分回执和 finalized。独立池不共用全局计数器，但没有用节点证据证明实际并行收益，也没有应用 TPS 成绩。其他 EVM 链同样能够实现这种机制。
- **撤回一定有效吗？** 撤回交易先进入链，旧 nonce 才会失效。已经执行的方案不能靠后来的撤回来逆转。
- **能保证线下入场吗？** 不能。机构需要真实预留名额并履约；身份核验留在机构侧，地址和席位关系仍公开可关联。
- **已有用户了吗？** 没有。本次是评委带操作的演示与测试网证明，接下来才进行机构和参加者验证。
